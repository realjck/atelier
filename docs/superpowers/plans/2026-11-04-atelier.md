# Atelier Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Tauri 2 desktop app that lists personal projects stored in SQLite, with one-click access to each project's folder, repository and live site.

**Architecture:** Rust owns the data: a `rusqlite` connection behind a `Mutex` in Tauri state, pure functions per table (`categories.rs`, `projects.rs`) unit-tested against an in-memory DB, thin `#[tauri::command]` wrappers. Opening folders/URLs also goes through Rust commands (validation + visible errors at one boundary). The React UI holds the loaded lists in memory, and does filtering/sorting/search with pure functions tested by Vitest.

**Tech Stack:** Tauri 2 (CLI 2.12.x), Rust 1.98, `rusqlite` (feature `bundled`), `chrono`, `thiserror`, `tauri-plugin-opener`, `tauri-plugin-dialog`; React 18/19 + TypeScript + Vite (versions from the scaffold), Vitest + Testing Library + jsdom.

**Spec:** `docs/superpowers/specs/2026-11-04-atelier-design.md`

## Global Constraints

- UI text, code, comments and README in English. No emoji anywhere.
- No chevrons / expandable rows. No header counter. Button label is exactly `+ New Project`.
- States (fixed, in this order): Idea, Draft, In Progress, On Hold, Completed, Archived. Stored slugs: `idea`, `draft`, `in_progress`, `on_hold`, `completed`, `archived`.
- Online = production URL non-empty. No network check.
- "All" filter hides Archived; "Archived" chip shows only archived; "Online" shows non-archived with prod URL.
- Deleting a category sets its projects' category to none.
- Category changes are staged in the panel and applied on Save only.
- Opening a missing local path shows a visible error.
- Logo: solid geometric "A", gradient `#8b6cff` -> `#5b3df5`, crossbar groove is a mask cut-out.
- Windows first. Use the dependency versions actually installed (lockfiles), not guessed ones.
- After each task: `npm test`, `npm run lint`, `cargo test` and `cargo clippy -- -D warnings` (from `src-tauri`) all pass before committing.

## Review Focus

1. Whitespace-only path/URL fields: must be stored as NULL, so the project is Offline and shows no path (Task 3 test `blank_optional_fields_become_null`).
2. Production URL typed without scheme (`example.com`): opening must still work, by prefixing `https://`. Non-http schemes (`file:`, `javascript:`) are rejected (Task 4 tests `normalize_url_*`).
3. Deleting a category used by projects: SQLite foreign keys are off by default, so `PRAGMA foreign_keys = ON` must be set or projects keep dangling ids (Task 2 test `deleting_category_nulls_projects`).
4. Clicking path / repo icon / Online inside a row must not also open the edit modal (Task 7 test `link_clicks_do_not_open_modal`).
5. Search must be case-insensitive and match path and category name too, so that "PORT" finds "Portfolio" (Task 5 test `search_is_case_insensitive_across_fields`).

Schema (migration 1, tracked with `PRAGMA user_version`):

```sql
CREATE TABLE categories (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL UNIQUE COLLATE NOCASE,
  color TEXT NOT NULL
);
CREATE TABLE projects (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL,
  category_id INTEGER REFERENCES categories(id) ON DELETE SET NULL,
  created TEXT NOT NULL,          -- YYYY-MM-DD
  state TEXT NOT NULL,
  local_path TEXT,
  repo_url TEXT,
  prod_url TEXT
);
```

Validation in `save_all`: name trimmed and non-empty, color matches `#rrggbb` (hex, case-insensitive), otherwise `AppError::Validation`.
